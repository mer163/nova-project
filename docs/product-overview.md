# Nova 产品说明

## 定位

面向研发协作团队的「类飞书项目」平台，替代当前分散在表格与聊天里的需求、缺陷与权限管理。核心不是复刻界面，而是把三件事收敛到同一处：**一张工单表、一套状态机、一层权限**。

## 解决的问题

| 现状痛点 | Nova 的做法 |
| --- | --- |
| 需求在文档、缺陷在群聊、任务在表格，编号各自一套 | 需求/缺陷/任务统一编号与统一列表，可按类型、空间、状态筛选 |
| 状态靠口头同步，经常跳过测试直接关闭 | 状态由工作流定义，非法流转服务端直接拒绝并提示允许的下一步 |
| 谁都能改，出了事查不到 | 角色 + 空间成员双层权限，所有写操作写审计日志 |
| 新人不知道流程走到哪 | 详情页展示可执行流转、操作历史和评论 |

## 三条主线

**需求管理**
- 列表 / 看板双视图，看板拖拽即流转
- 优先级 P0–P3、负责人、截止日期、标签、估算
- 需求流程：待评估 → 已规划 → 开发中 → 待测试 → 已完成

**缺陷管理**
- 独立 `BUG-` 编号，与需求共享列表和看板
- 缺陷流程：待处理 → 修复中 → 待验证 → 已关闭 / 不予修复
- 验证不通过可退回修复中，形成闭环

**权限管理**
- 全局角色：管理员、项目负责人、研发、测试、访客，权限项可自定义
- 空间角色：负责人 / 可编辑 / 只读，按空间分别授权
- 未加入空间的用户即使有全局读权限也看不到该空间工单

## 角色与典型路径

1. **项目负责人**创建空间、邀请成员、录入需求并「纳入规划」。
2. **研发**认领需求，推进到「开发中」；发现缺陷时在同空间登记 `BUG-`，走缺陷流程。
3. **测试**验证缺陷，通过则「已关闭」，不通过则退回「修复中」。
4. **访客 / 干系人**只读查看进度，不出现编辑入口。

## 信息架构

```
工作台      待办、类型分布、成员负载、进行中迭代、最近更新
需求与缺陷   列表 / 看板 / 详情抽屉（编辑、流转、评论、附件、历史）
迭代        迭代卡片、进度、成员负载，可查看并筛选所属工单
通知        指派、状态变更、评论三类通知，未读角标
空间        空间卡片 → 成员与角色
成员与权限   成员、角色权限矩阵、工作流、审计日志
设置        账号信息、修改密码、我的权限
```

## 界面原则

- 侧栏 + 内容区，和飞书项目的操作习惯一致，迁移成本低
- 状态用颜色区分，同一套颜色贯穿列表、看板、详情
- 只读用户的编辑入口整体隐藏，而不是点了才报错
- 危险操作（删除工单、移除成员、删除角色）二次确认

## 迭代节奏

按双周节奏组织工作：项目负责人建迭代并写清目标，成员把需求与缺陷挂到迭代上，迭代卡片实时显示完成进度与估算点数。迭代结束后工单仍保留在空间内，只是解绑关系。

## 通知与批量

关注工单相当于订阅：状态变更、被指派、他人评论都会进入通知中心，只读用户也可以关注。列表支持多选后批量调整负责人、优先级和迭代，越权的条目会被自动跳过并告知条数。

## 与完整版的差距

当前是可运行的原型：单机 JSON 存储、本地账号体系、附件存本地磁盘。生产化需要补：关系型数据库与迁移、SSO/OIDC、字段级权限、附件对象存储与病毒扫描、邮件/企微推送、跨空间报表、操作幂等与并发控制。
